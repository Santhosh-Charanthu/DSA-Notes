Dijkstra's Algorithm

1. What is Dijkstra's Algorithm?

Dijkstra's algorithm is a Single Source Shortest Path (SSSP) algorithm used to find the shortest distance from a source vertex to all other vertices in a weighted graph.

⭐Important condition

Dijkstra works when:

All edge weights are non-negative (weight >= 0).

It can handle:

  • Positive weights ✅
  • Zero-weight edges ✅
  • Cycles ✅
  • Directed graphs ✅
  • Undirected graphs ✅

It does not work correctly with negative-weight edges.

2. Core Intuition ⭐

Dijkstra follows a greedy approach.

At every step:

Pick the unprocessed vertex having the smallest known distance from the source, and finalize its distance.

Why is it safe to finalize?

Because all edge weights are non-negative.

Suppose we already have:

dist[B] = 5
dist[C] = 8

We choose B because it has the smaller distance.

Any path going through C would have:

dist[C] + edge weight
≥ 8 + 0
≥ 8

So it cannot later produce a distance smaller than 5.

Therefore:

With non-negative edges, once we select the minimum-distance unprocessed vertex, its distance is final.

This is the fundamental reason Dijkstra works.

3. Relaxation

For every edge:

u ----wt----> v

check:

dist[u] + wt < dist[v]

If true:

dist[v] = dist[u] + wt

In code:

if (dist[u] + wt < dist[v]) {
    dist[v] = dist[u] + wt;
}

Meaning

"Can I reach v more cheaply by going through u?"

4. Why Does Dijkstra Fail With Negative Edges?

Dijkstra assumes:

Once a vertex is finalized, its distance can never become smaller.

This assumption depends on:

edge weight >= 0

Consider:

A → B = 2
A → C = 5
C → B = -10

Starting from A:

dist[B] = 2
dist[C] = 5

Dijkstra chooses B because:

2 < 5

and finalizes:

dist[B] = 2

But later:

A → C → B
= 5 + (-10)
= -5

The actual shortest distance is -5.

Dijkstra has already finalized B, so its greedy decision becomes incorrect.

Therefore:

Dijkstra cannot safely handle negative-weight edges.

5. Why Does Dijkstra Handle Cycles?

A common misconception is:

"Dijkstra doesn't work on cyclic graphs."

❌ False.

Dijkstra can handle cycles.

For example:

A → B → C
↑       ↓
└───────┘

As long as all edge weights are non-negative, Dijkstra works.

The visited/finalized mechanism prevents repeatedly processing a vertex unnecessarily.

⭐Important
Cycle ≠ Problem
Negative weight = Problem

6. Algorithm Using Priority Queue

The efficient implementation uses a Min Priority Queue.

We store:

(distance, node)

The priority queue always gives us the node with the smallest distance.

Basic structure

int[] dist = new int[V];

Arrays.fill(dist, Integer.MAX_VALUE);

dist[src] = 0;

PriorityQueue<Pair> pq =
    new PriorityQueue<>((a, b) -> a.distance - b.distance);

pq.add(new Pair(0, src));

while (!pq.isEmpty()) {

    Pair current = pq.poll();

    int distance = current.distance;
    int node = current.node;

    if (distance > dist[node]) {
        continue;
    }

    for (Edge edge : adj[node]) {

        int next = edge.to;
        int wt = edge.weight;

        if (distance + wt < dist[next]) {

            dist[next] = distance + wt;

            pq.add(new Pair(
                dist[next],
                next
            ));
        }
    }
}

7. Why Use a Priority Queue?

Suppose we have:

A → B = 10
A → C = 3
A → D = 7

After processing A:

B = 10
C = 3
D = 7

We want to process:

C

first because:

3 < 7 < 10

A Min Heap / Priority Queue efficiently gives us the smallest distance.

Without a priority queue, we may need to scan all vertices to find the minimum.

With a priority queue:

poll() → O(log V)
add()  → O(log V)

8. Important Optimization in Java

You may see:

if (distance > dist[node]) {
    continue;
}

Why?

Suppose we previously inserted:

(node = B, distance = 10)

Later we discover:

(node = B, distance = 5)

The priority queue can contain both:

(5, B)
(10, B)

We process (5, B) first.

When (10, B) eventually comes out:

distance = 10
dist[B] = 5

Therefore:

10 > 5

So we skip it.

This is called stale entry checking.

9. Time Complexity

For adjacency list + binary min heap:

O((V + E) log V)

Often written as:

O(E log V)

for a connected graph where E >= V-1.

Why?

We process vertices and edges, and priority queue operations cost log V.

Conceptually:

Graph traversal
        ↓
V + E
        ↓
Priority Queue
        ↓
log V

Therefore:

O((V + E) log V)

10. Space Complexity

We maintain:

dist[]          → O(V)
priority queue  → O(V) to O(E), depending on implementation/state
adjacency list  → O(V + E)

For the complete graph representation:

O(V + E)

Additional algorithmic space excluding the graph itself is typically:

O(V)

11. Dijkstra vs Bellman-Ford

Feature Dijkstra Bellman-Ford
Positive edges ✅ ✅
Zero edges ✅ ✅
Negative edges ❌ ✅
Negative cycle detection ❌ ✅
Main idea Greedy Repeated relaxation
Time O((V+E) log V) O(VE)
Faster generally ✅ ❌
Single-source shortest path ✅ ✅

Fundamental difference

Dijkstra:

"Pick the closest vertex and finalize it."

Bellman-Ford:

"Keep relaxing all edges repeatedly until shortest distances propagate."

12. Dijkstra's Most Important Proof

Why can Dijkstra finalize a vertex?

Suppose B is currently the closest unprocessed vertex:

dist[B] = 5

Any alternative path to B must first go through some other unprocessed vertex C.

Since B is currently the closest:

dist[C] >= 5

And because edge weights are non-negative:

dist[C] + weight(C,B) >= 5

Therefore, going through another unprocessed vertex cannot produce a value smaller than 5.

Hence:

B = 5

is final.

This proof breaks when negative edges exist.

If:

dist[C] = 8
C → B = -10

then:

8 + (-10) = -2

which is smaller than 5.

That's exactly why Dijkstra fails with negative edges.

13. Common Interview Questions

Q1. Why does Dijkstra fail with negative edges?

Because a negative edge can produce a shorter path to a vertex after that vertex has already been finalized.

Q2. Can Dijkstra handle cycles?

Yes.

Cycles are not a problem as long as all edge weights are non-negative.

Q3. Can Dijkstra detect negative cycles?

No.

Bellman-Ford is used for negative-cycle detection.

Q4. Why use a priority queue?

To efficiently retrieve the unprocessed vertex with the smallest known distance.

Q5. Why do we use a visited array?

It can be used to mark finalized vertices, although many priority-queue implementations instead use stale-entry checking:

if (distance > dist[node]) continue;

⭐ Dijkstra Memory Trick

Remember it as:

Initialize distances
       ↓
Put source in Min Heap
       ↓
Take minimum-distance node
       ↓
Relax its edges
       ↓
Update distances + push into heap
       ↓
Repeat

The most important condition:

weight >= 0

The most important intuition:

"Always process the currently closest vertex because, with non-negative edge weights, nothing farther away can later provide a cheaper route to it."

One-line interview definition:

Dijkstra is a greedy single-source shortest-path algorithm that repeatedly selects the unprocessed vertex with the minimum tentative distance and relaxes its outgoing edges; it is correct when all edge weights are non-negative.
