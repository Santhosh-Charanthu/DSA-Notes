Word Ladder

🔗 Problem
🧠Intuition
  • Think of each word as a node in a graph.
  • An edge exists between two words if they differ by exactly one character.
  • We need the shortest transformation sequence, which means the shortest path in an unweighted graph.
  • Since every transformation has the same cost (1 step), BFS guarantees the shortest path.

How to Think

  • Instead of explicitly building the graph (which is expensive), generate neighbours on the fly.
  • For every character position in the current word:
    • Replace it with every letter from 'a' to 'z'.
    • If the generated word exists in the dictionary, it is a valid neighbour.
  • Use BFS to explore level by level.
  • The first time we reach endWord, we have found the shortest transformation.
🧾Algorithm
  1. Store all words from wordList in a HashSet for O(1) lookup.
  2. If endWord is not in the set, return 0.
  3. Initialize a queue with (beginWord, level = 1).
  4. Remove beginWord from the set (if present) to avoid revisiting.
  5. While the queue is not empty:
    • Pop the current word.
    • If it equals endWord, return its level.
    • For every character position:
      • Replace it with 'a' to 'z'.
      • If the new word exists in the set:
        • Push it into the queue with level + 1.
        • Remove it from the set (mark as visited).
  6. If BFS ends without reaching endWord, return 0.

Why It Works

  • Every valid transformation is one edge.
  • BFS explores all words at distance d before exploring distance d + 1.
  • Therefore, the first time endWord is reached, it is through the minimum number of transformations.
⏱️Time Complexity

Let:

  • N = Number of words

  • L = Length of each word

  • Time: O(N × L × 26)

  • Space: O(N)

Interview Recognition Pattern

Use this approach when:

  • Find the minimum number of transformations.
  • Every transformation has the same cost.
  • State changes by modifying one character, digit, or property.
  • The graph is implicit (neighbours are generated instead of stored).

Why Generate Neighbours Instead of Building the Graph?

Suppose:

  • N = 5000
  • L = 10

Build Graph

  • Compare every pair of words.
  • Time: O(N² × L)

Generate On the Fly

  • For each word, try changing every position to 26 letters.
  • Time: O(L × 26) per word.

This is much faster and avoids constructing all graph edges.

🔍Key Observation
  • Word = Node
  • One letter change = Edge
  • Shortest transformation = Shortest path
  • Unweighted graph = BFS

Memory Trick

Whenever you see "minimum transformations" where each transformation has equal cost, think of the states as graph nodes and solve it using BFS.
