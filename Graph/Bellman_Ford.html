Bellman-Ford Algorithm

1. What is Bellman-Ford?

Bellman-Ford is a Single Source Shortest Path (SSSP) algorithm used to find the shortest distance from one source vertex to all other vertices.

Special features

  • Works with positive and negative edge weights
  • Can detect a negative-weight cycle
  • Works for directed and undirected graphs (with appropriate edge representation)

2. Core Intuition

The main idea is Relaxation.

For every edge:

u ----wt----> v

we check:

dist[u] + wt < dist[v]

If true:

dist[v] = dist[u] + wt

In simple words:

"Can I reach v with a shorter distance by going through u?"

3. Why Do We Relax All Edges V-1 Times?

This is the most important concept in Bellman-Ford.

Key fact:

A shortest path without a cycle can contain at most V-1 edges.

Why?

If there are V vertices:

A → B → C → D → E

There are:

5 vertices
4 edges

To have a path with more than V-1 edges, we must visit some vertex more than once.

That creates a cycle.

Therefore:

Maximum edges in a simple shortest path = V - 1

Why does this matter?

Bellman-Ford relaxes every edge repeatedly so that shortest-distance information can propagate along the path.

For example:

A → B → C → D

Information may propagate like:

A → B        1 edge
A → B → C    2 edges
A → B → C → D  3 edges

Since the longest possible simple shortest path has at most V-1 edges, V-1 relaxation rounds are sufficient to discover every shortest path that does not involve a negative cycle.

🧠 The key intuition

V - 1 doesn't mean we "want" to traverse V-1 edges. It means a shortest path can never need more than V-1 edges.

4. Why Do We Need One More Traversal?

After completing:

V - 1 rounds

we perform one additional traversal of all edges.

for (int[] edge : edges) {

    int u = edge[0];
    int v = edge[1];
    int wt = edge[2];

    if (dist[u] != INF && dist[u] + wt < dist[v]) {
        return new int[]{-1};
    }
}

Why?

After V-1 rounds:

Every shortest path without a cycle should already have its minimum possible distance.

So if we can still reduce a distance, something unusual is happening.

The path must require more than V-1 edges.

But a path with more than V-1 edges must contain a cycle.

If traversing that cycle keeps reducing the distance, the cycle must have a:

Negative total weight

Therefore:

Distance can still decrease
        ↓
Path requires another edge
        ↓
There is a cycle
        ↓
Cycle decreases distance
        ↓
Negative-weight cycle

Hence, the extra traversal is used for:

Negative Cycle Detection

5. Why dist[u] != INF Is Checked?

if (dist[u] != INF && dist[u] + wt < dist[v])

The first condition:

dist[u] != INF

means:

u must be reachable from the source.

We only want to detect a negative cycle that is reachable from the source.

An unreachable negative cycle should not affect the shortest paths from our source.

6. Complete Algorithm

Step 1: Initialize distances

dist[source] = 0
dist[all other vertices] = INF

Step 2: Relax all edges V-1 times

for (int i = 0; i < V - 1; i++) {

    for (int[] edge : edges) {

        int u = edge[0];
        int v = edge[1];
        int wt = edge[2];

        if (dist[u] != INF &&
            dist[u] + wt < dist[v]) {

            dist[v] = dist[u] + wt;
        }
    }
}

Purpose:

Find shortest paths assuming there is no reachable negative cycle.

Step 3: Perform one additional traversal

for (int[] edge : edges) {

    int u = edge[0];
    int v = edge[1];
    int wt = edge[2];

    if (dist[u] != INF &&
        dist[u] + wt < dist[v]) {

        return new int[]{-1};
    }
}

Purpose:

Check whether any distance can still be reduced.

If yes:

→ Reachable negative-weight cycle exists

Otherwise:

→ No reachable negative-weight cycle
→ Return shortest distances

7. Example of Negative Cycle

Consider:

A ──2──> B
↑       │
│       -4
│       ↓
└──1──── C

Cycle:

A → B → C → A

Total weight:

2 + (-4) + 1 = -1

Every time we traverse this cycle:

distance decreases by 1

Therefore, there is no finite shortest distance.

The extra traversal detects that:

dist[u] + wt < dist[v]

is still possible after V-1 rounds.

Hence:

return new int[]{-1};

8. Time Complexity

There are two nested operations:

V - 1 rounds
        ×
E edges

Therefore:

Time = O(V × E)

The additional negative-cycle check scans all edges once:

O(E)

So overall:

O(VE)

9. Space Complexity

We mainly store:

dist[] → O(V)

Therefore:

Space = O(V)

10. Bellman-Ford vs Dijkstra

Feature Bellman-Ford Dijkstra
Positive edges ✅ ✅
Negative edges ✅ ❌
Negative cycle detection ✅ ❌
Approach Repeated relaxation Greedy
Time O(VE) O((V+E) log V) with min-heap

Fundamental difference

Dijkstra relies on a greedy choice that assumes once a vertex is finalized, its distance cannot improve. Bellman-Ford makes no such assumption and repeatedly relaxes all edges.

⭐ Interview Memory Trick

Remember Bellman-Ford as:

Initialize
    ↓
Relax ALL edges V-1 times
    ↓
One EXTRA pass
    ↓
Can distance still decrease?
    ↓
YES → Negative cycle
NO  → Shortest distances

The two most important facts:

Why V-1? A shortest path without a cycle can contain at most V-1 edges.

Why one extra pass? If a distance can still decrease after V-1 rounds, the path must contain a cycle whose total weight is negative.

One-line definition

Bellman-Ford repeatedly relaxes every edge V-1 times to find shortest paths, then performs one extra relaxation pass to detect a reachable negative-weight cycle.
