LeetCode 2594 — Minimum Time to Repair Cars

🔗 Problem

1. Why this comes under Binary Search on Answers

We need to find the minimum amount of time required to repair at least cars cars.

We are not searching for time in an array. We are searching over possible time values.

For a candidate time mid:

  • If all cars can be repaired within mid time → mid is possible.
  • If fewer than cars can be repaired → mid is impossible.

As the available time increases, the number of cars that can be repaired can only increase:

FALSE FALSE FALSE TRUE TRUE TRUE

So this is Binary Search on Answer → Minimize the Maximum / Minimum Feasible Value / First TRUE.

2. What is the answer I'm searching for?

We are searching for the minimum time required to repair all cars.

mid = candidate amount of time available

For each mechanic with rank r:

time to repair x cars = r * x²

So for a given mid, we need to determine how many cars each mechanic can repair within that time.

3. What is the smallest possible answer?

min(ranks).

The fastest mechanic has the smallest rank.

Even repairing one car requires at least:

minRank * 1² = minRank

So the answer cannot be smaller than the fastest mechanic's rank.

Therefore:

low = min(ranks)

4. What is the largest possible answer?

minRank * cars².

We can always give all cars to the fastest mechanic.

If the fastest mechanic has rank minRank, repairing all cars takes:

minRank * cars²

Therefore this is a guaranteed upper bound.

So:

high = minRank * cars²

The search range is:

minRank <= answer <= minRank * cars²

5. If I assume mid is the answer

Assume:

mid = amount of time available.

For a mechanic with rank r, if they repair x cars:

r * x² <= mid

Therefore:

x² <= mid / r

So:

x <= sqrt(mid / r)

Thus, the number of cars that mechanic can repair within mid time is:

floor(sqrt(mid / r))

Calculate this for every mechanic and add them:

totalCars = Σ floor(sqrt(mid / rank))

If totalCars >= cars

We can repair all required cars within mid time.

So mid is possible.

But we want the minimum time, so try a smaller value:

high = mid - 1

If totalCars < cars

We don't have enough repair capacity.

So mid is too small and we need more time:

low = mid + 1

Therefore:

possible → LEFT

not possible → RIGHT

We are looking for the first TRUE.

6. Main idea of isPossible()

For a candidate time mid:

  1. Take each mechanic's rank.

  2. Calculate how many cars that mechanic can repair within mid time:

    floor(sqrt(mid / rank))

  3. Add the cars repaired by all mechanics.

  4. Check whether the total is at least cars.

Example

Suppose:

ranks = [4, 2]

mid = 20

For rank 4:

4 * x² <= 20

x <= sqrt(20 / 4)

x <= sqrt(5)

So this mechanic can repair:

2 cars

For rank 2:

x <= sqrt(20 / 2)

x <= sqrt(10)

So this mechanic can also repair:

3 cars

Total:

2 + 3 = 5 cars

Therefore, if:

cars <= 5

then mid = 20 is feasible.

Key mathematical idea

Convert the time constraint into the maximum number of cars each mechanic can repair, then check whether the combined capacity is enough.

7. Main intuition

Simple idea

We don't know the minimum repair time, so guess it as mid.

Then ask:

"If all mechanics have mid time available, can they collectively repair at least cars cars?"

For each mechanic, calculate how many cars they can repair in that time.

If the total is enough, mid works → try less time.

If the total is not enough, we need more time → try a larger value.

In one flow

Answer = minimum time required to repair all cars

→ Search in [minRank, minRank * cars²]

→ Assume mid is the available time

→ For every mechanic calculate:

floor(sqrt(mid / rank))

→ Add the number of cars repaired by all mechanics

→ totalCars >= cars → possible → go LEFT

→ totalCars < cars → impossible → go RIGHT

→ Return the first feasible time

Pattern to remember

Minimum feasible answer → First TRUE → if mid works, move LEFT.

⭐Important implementation points

  • For a mechanic with rank r:

    time = r * cars²

  • Therefore, for a fixed mid:

    cars repaired = floor(sqrt(mid / r))

  • low = min(ranks) because the fastest mechanic needs at least minRank time to repair one car.

  • high = minRank * cars² because the fastest mechanic can repair all cars alone within this time.

  • The total number of repaired cars can be very large, so totalCars should be long, not int.

  • mid should be long because the upper bound can be very large.

  • The feasibility check can return true immediately once totalCars >= cars.

  • This problem's isPossible() is based on mathematical capacity calculation, unlike 1011/410 where feasibility is found by greedily forming partitions.
