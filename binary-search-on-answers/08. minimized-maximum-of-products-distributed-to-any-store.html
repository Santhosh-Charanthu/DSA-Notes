LeetCode 2064 — Minimized Maximum of Products Distributed to Any Store

🔗 Problem

1. Why this comes under Binary Search on Answers

We need to minimize the maximum number of products assigned to any store.

We are not searching for an answer inside the quantities array. We are searching over possible values of the maximum products allowed per store.

For a candidate mid:

  • If we can distribute all products using at most n stores while giving each store at most mid products → mid is possible.
  • If we need more than n stores → mid is too small.

The feasibility pattern is:

FALSE FALSE FALSE TRUE TRUE TRUE

So this is Binary Search on Answer → Minimize the Maximum → First TRUE.

2. What is the answer I'm searching for?

We are searching for the minimum possible maximum number of products assigned to any store.

mid = maximum number of products allowed in one store

For example, if:

mid = 5

then every store can receive at most 5 products.

3. What is the smallest possible answer?

1.

If there are enough stores, every store could receive only one product.

Therefore:

low = 1

4. What is the largest possible answer?

max(quantities).

A store never needs to receive more products than the largest quantity of any product type.

If:

quantities = [11, 6, 7]

then 11 is the largest possible maximum allocation.

Therefore:

high = max(quantities)

So:

1 <= answer <= max(quantities)

5. If I assume mid is the answer

Assume:

mid = maximum products allowed per store

For each product type with quantity products, calculate how many stores are required if each store can receive at most mid products.

Required stores:

ceil(quantity / mid)

Add this for every product type.

If stores <= n

We can distribute all products using at most n stores.

Therefore mid is possible.

But we want to minimize the maximum allocation, so try a smaller value:

high = mid - 1

If stores > n

We need more stores than we have.

Therefore mid is too small, so we need to allow more products per store:

low = mid + 1

Therefore:

possible → LEFT

not possible → RIGHT

We are looking for the first TRUE.

6. Main idea of isPossible()

For a candidate mid:

  1. Consider each product type independently.

  2. Calculate how many stores are required for that quantity if each store can receive at most mid products:

    storesRequired = ceil(quantity / mid)

  3. Add the stores required for all product types.

  4. Check whether the total number of stores is at most n.

Example

quantities = [11, 6, 7]

n = 6

Suppose:

mid = 4

For 11 products:

ceil(11/4) = 3 stores

For 6 products:

ceil(6/4) = 2 stores

For 7 products:

ceil(7/4) = 2 stores

Total:

3 + 2 + 2 = 7 stores

But:

7 > 6

Therefore:

mid = 4 is impossible.

Try a larger value.

Why do we calculate stores independently?

Each store can receive products of at most one product type.

Therefore, if a product type has quantity products, we independently determine how many stores are needed for that type.

The total number of required stores is simply the sum across all product types.

Key mathematical idea

For every quantity:

required stores = ceil(quantity / mid)

Then:

total stores = Σ ceil(quantity / mid)

Feasible when:

total stores <= n

7. Main intuition

Simple idea

We don't know the minimum possible maximum allocation, so guess it as mid.

Then ask:

"If each store can receive at most mid products, how many stores do I need to distribute everything?"

If the required stores are within n, mid works → try a smaller maximum.

If we need more than n stores, mid is too small → allow more products per store.

In one flow

Answer = minimum possible maximum products per store

→ Search in [1, max(quantities)]

→ Assume mid is the maximum allowed per store

→ For every product type calculate ceil(quantity / mid)

→ Add the required stores

→ stores <= n → possible → go LEFT

→ stores > n → impossible → go RIGHT

→ Return the first feasible value

Pattern to remember

Minimize the Maximum → Binary Search on Answer → First TRUE → if mid works, move LEFT.

⭐Important implementation points

  • A store can receive products from only one product type.

  • For each product type, calculate its required number of stores independently.

  • low = 1 because the maximum allocation can theoretically be 1.

  • high = max(quantities) because no store needs more than the largest product quantity.

  • Integer arithmetic can replace Math.ceil():

    (quantity + mid - 1) / mid

  • If constraints allow the total store count to become large, use long for stores.
