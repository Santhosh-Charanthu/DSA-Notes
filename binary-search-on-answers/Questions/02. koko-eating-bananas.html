LeetCode 875 — Koko Eating Bananas

🔗 Problem

1. Why this comes under Binary Search on Answers

We are not searching for a speed in a sorted array. We are searching for the minimum eating speed that allows Koko to finish all bananas within h hours.

For a fixed speed mid:

  • If Koko can finish within h hours → mid is possible.
  • If she needs more than h hours → mid is impossible.

As speed increases, the required hours only decrease:

FALSE FALSE FALSE TRUE TRUE TRUE

So this is Binary Search on Answer → Minimum Feasible Value / First TRUE.

2. What is the answer I'm searching for?

We are searching for the minimum eating speed k (bananas/hour) such that Koko can finish all banana piles within h hours.

mid = eating speed

3. What is the smallest possible answer?

1.

Koko must eat at least 1 banana per hour.

So:

low = 1

4. What is the largest possible answer?

max(piles).

If Koko eats at the speed equal to the largest pile, she can finish every pile in at most one hour per pile.

Any speed greater than the largest pile is unnecessary.

So:

high = max(piles)

5. If I assume mid is the answer

Assume mid is Koko's eating speed.

We calculate how many hours she needs for every pile.

For a pile of pile bananas:

hours = ceil(pile / mid)

Total:

totalHours = Σ ceil(pile / mid)

If totalHours <= h

Koko can finish within the allowed time.

Therefore mid is possible.

But we want the minimum speed, so try a smaller speed:

high = mid - 1

If totalHours > h

Koko is too slow.

We need a larger speed:

low = mid + 1

Therefore:

possible → LEFT
not possible → RIGHT

We are looking for the first TRUE.

6. Main idea of isPossible()

For a candidate speed mid:

  1. For every pile, calculate how many hours Koko needs:

    ceil(pile / mid)

  2. Add the hours for all piles.

  3. Compare the total hours with h.

    totalHours <= h → possible

    totalHours > h → impossible

The important idea is:

Given a speed, calculate the exact amount of time required.

We don't need to simulate hour by hour.

For example:

piles = [3, 6, 7, 11]

mid = 5

Hours:

ceil(3/5) = 1
ceil(6/5) = 2
ceil(7/5) = 2
ceil(11/5) = 3

Total:

1 + 2 + 2 + 3 = 8 hours

So if h >= 8, speed 5 is feasible.

7. Main intuition

Simple idea

Guess Koko's eating speed mid.

Ask:

"If Koko eats mid bananas per hour, can she finish all piles within h hours?"

If yes, the speed works, but maybe we can eat even slower → search LEFT.

If no, Koko is too slow → search RIGHT.

In one flow

Answer = minimum feasible eating speed

→ Search in [1, max(piles)]

→ Assume mid is the speed

→ Calculate total hours required

→ totalHours <= h → possible → go LEFT

→ totalHours > h → impossible → go RIGHT

→ Return the first feasible speed

Pattern to remember

Minimum feasible answer → First TRUE → if mid works, move LEFT.

⭐Important implementation point

The hours can become large when there are many piles, so check the constraints and use long for totalHours if necessary.

Your implementation uses Math.ceil(pile / (double)m), which is correct. An integer-only alternative is:

(pile + m - 1) / m
