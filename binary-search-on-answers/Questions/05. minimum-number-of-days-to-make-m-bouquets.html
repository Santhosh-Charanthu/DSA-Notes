LeetCode 1482 — Minimum Number of Days to Make m Bouquets

🔗 Problem

1. Why this comes under Binary Search on Answers

We need to find the minimum number of days after which we can make at least m bouquets.

For a candidate day mid:

  • Flowers with bloomDay[i] <= mid are available.
  • If we can make at least m bouquets → mid is possible.
  • If we cannot make m bouquets → mid is impossible.

As the number of days increases, more flowers become available, so feasibility is monotonic:

FALSE FALSE FALSE TRUE TRUE TRUE

Therefore, this is Binary Search on Answer → Minimum Feasible Value / First TRUE.

2. What is the answer I'm searching for?

We are searching for the minimum number of days needed to make at least m bouquets, where every bouquet requires k adjacent flowers.

mid = candidate number of days

3. What is the smallest possible answer?

The smallest bloom day in the array.

low = min(bloomDay)

We cannot make any flower available before the earliest flower blooms.

4. What is the largest possible answer?

The largest bloom day in the array.

high = max(bloomDay)

By this day, every flower has bloomed, so if making m bouquets is possible at all, it must be possible by this day.

Therefore:

min(bloomDay) <= answer <= max(bloomDay)

⭐Important edge case

We need m * k flowers in total.

If:

m * k > bloomDay.length

then it is impossible to make the required bouquets at all.

So the answer is -1.

5. If I assume mid is the answer

Assume mid is the number of days we are willing to wait.

A flower is available if:

bloomDay[i] <= mid

Now scan the array and look for consecutive available flowers.

If bloomDay[i] <= mid

The flower has bloomed, so increase the current consecutive count.

When:

count == k

we have enough adjacent flowers to make one bouquet:

bouquets++

Then reset:

count = 0

because those flowers have already been used.

If bloomDay[i] > mid

The flower has not bloomed yet.

It breaks the consecutive sequence, so:

count = 0

If bouquets >= m

mid is possible.

But we want the minimum number of days, so search for a smaller value:

high = mid - 1

If bouquets < m

mid is not enough.

We need more days:

low = mid + 1

Therefore:

possible → LEFT

not possible → RIGHT

We are looking for the first TRUE.

6. Main idea of isPossible()

For a candidate day mid:

  1. Consider every flower whose bloomDay <= mid as available.
  2. Count consecutive available flowers.
  3. Whenever we get k consecutive available flowers, make one bouquet and reset the count.
  4. If an unbloomed flower appears, reset the consecutive count because adjacency is broken.
  5. At the end, check whether we made at least m bouquets.

Example

bloomDay = [1,10,3,10,2]

Suppose:

mid = 3

Available flowers:

[Y, N, Y, N, Y]

There are no 2 consecutive available flowers.

So if:

k = 2

then:

bouquets = 0

Therefore mid = 3 is impossible.

Example with a valid bouquet

bloomDay = [1,2,3,10,2,3]

Suppose:

mid = 3

Available:

[Y,Y,Y,N,Y,Y]

If:

k = 2

we can form:

[1,2] → bouquet 1

then:

[3,10,2,3]

The 10 breaks adjacency, so the final [2,3] forms:

bouquet 2

Therefore:

bouquets = 2

If m = 2, mid = 3 is possible.

Key greedy idea

Whenever we find k consecutive bloomed flowers, immediately use them to form a bouquet.

This is safe because using the earliest possible group leaves the remaining flowers available for future bouquets.

7. Main intuition

Simple idea

Guess a day mid and ask:

"If I wait until day mid, can I make at least m bouquets using groups of k adjacent bloomed flowers?"

If yes, we don't need to wait that long → search LEFT.

If no, we need more days → search RIGHT.

In one flow

Answer = minimum feasible day

→ Search in [min(bloomDay), max(bloomDay)]

→ Assume mid is the number of days

→ Mark flowers with bloomDay <= mid as available

→ Count consecutive available flowers

→ Every k consecutive flowers = 1 bouquet

→ bouquets >= m → possible → go LEFT

→ bouquets < m → impossible → go RIGHT

→ Return the first feasible day

Pattern to remember

Minimum feasible answer → First TRUE → if mid works, move LEFT.

⭐Important implementation points
  • Adjacency matters. You cannot combine arbitrary bloomed flowers.
  • An unbloomed flower resets the consecutive count.
  • When count == k, immediately form a bouquet and reset count.
  • Before binary search, check whether m * k > n. If so, return -1.
  • Use long for m * k if constraints can make the multiplication overflow int.
