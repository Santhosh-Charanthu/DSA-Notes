LeetCode 2517 — Maximum Tastiness of Candy Basket

🔗 Problem

1. Why this comes under Binary Search on Answers

We need to maximize the minimum absolute difference between the prices of any two selected candies.

We are not searching for the answer inside the price array. We are searching over possible values of the minimum price difference.

For a candidate mid:

  • If we can select at least k candies such that the difference between consecutive selected prices is at least mid → mid is possible.
  • If we cannot select k candies → mid is impossible.

As mid increases, selecting k candies becomes harder:

TRUE TRUE TRUE TRUE FALSE FALSE FALSE

So this is Binary Search on Answer → Maximize the Minimum → Last TRUE.

2. What is the answer I'm searching for?

We are searching for the maximum possible minimum difference between the prices of any two selected candies.

mid = minimum price difference required between selected candies

For example, if:

mid = 8

we are asking:

"Can I select k candies such that the difference between every pair of selected candies is at least 8?"

The largest feasible mid is the answer.

3. What is the smallest possible answer?

1.

Since prices are distinct and are integers, the smallest possible positive difference is 1.

Therefore:

low = 1

4. What is the largest possible answer?

max(price) - min(price).

The largest possible difference can only be obtained between the cheapest and most expensive candy.

Therefore, after sorting:

high = price[n - 1] - price[0]

So:

1 <= answer <= max(price) - min(price)

5. If I assume mid is the answer

Assume:

mid = minimum price difference required between selected candies.

Since the prices are sorted, start by selecting the cheapest candy.

Then scan from left to right.

For every price:

price[i] - lastSelected >= mid

If true, select that candy and update:

lastSelected = price[i]

If count >= k

We successfully selected enough candies.

Therefore mid is possible.

But we want to maximize the minimum difference, so try a larger value:

low = mid + 1

If count < k

We cannot select enough candies with this minimum difference.

Therefore mid is too large:

high = mid - 1

Therefore:

possible → RIGHT

not possible → LEFT

We are looking for the last TRUE.

6. Main idea of isPossible()

For a candidate mid:

  1. Sort the prices.

  2. Select the first/cheapest candy.

  3. Keep track of the last selected price.

  4. Scan from left to right.

  5. If:

    currentPrice - lastSelected >= mid

    select the current candy.

  6. Continue until either:

    • k candies are selected → return true
    • the array ends without selecting k candies → return false

Example

price = [13, 5, 1, 8, 21, 2]

After sorting:

[1, 2, 5, 8, 13, 21]

Suppose:

k = 3

and:

mid = 8

Start with:

selected = [1]

Check:

2 - 1 = 1 < 8 → skip

5 - 1 = 4 < 8 → skip

8 - 1 = 7 < 8 → skip

13 - 1 = 12 >= 8 → select 13

selected = [1, 13]

Then:

21 - 13 = 8 >= 8 → select 21

selected = [1, 13, 21]

Now:

count = 3 = k

Therefore:

mid = 8 is possible.

Why can we start with the smallest price?

We are only trying to determine whether mid is possible.

Choosing the smallest price gives the maximum amount of space for selecting future candies.

The feasibility check does not need to find the same basket as the problem's example.

For example, the problem may choose:

[5, 13, 21]

while our greedy check chooses:

[1, 13, 21]

Both have minimum difference 8.

Therefore, both prove that mid = 8 is feasible.

Why do we choose the earliest possible price?

For a fixed mid, choosing the earliest valid price leaves the maximum possible space for the remaining candies.

So the greedy strategy is:

Always select the earliest price that is at least mid away from the last selected price.

This maximizes the number of candies we can select for the candidate mid.

7. Main intuition

Simple idea

We don't know the maximum possible tastiness, so guess it as mid.

Then ask:

"If the minimum required price difference is mid, can I select k candies?"

If yes, mid works, so try a larger difference.

If no, mid is too large, so try a smaller difference.

In one flow

Answer = maximum possible minimum price difference

→ Sort the prices

→ Search in [1, max(price) - min(price)]

→ Assume mid is the required minimum difference

→ Select the first candy

→ Greedily select the earliest possible next candy

→ Count selected candies

→ count >= k → possible → go RIGHT

→ count < k → impossible → go LEFT

→ Return the last feasible value

Pattern to remember

Maximize the Minimum → Binary Search on Answer → Last TRUE → if mid works, move RIGHT.

⭐Important implementation points
  • Sort the prices before the feasibility check.
  • mid represents the minimum required difference, not the actual difference between every pair.
  • low = 1.
  • high = max(price) - min(price).
  • The feasibility check should use count >= k, not count == k.
  • Once k candies can be selected, return true immediately.
  • The greedy choice is to select the earliest possible candy satisfying the required difference.
  • The feasibility check only needs to prove that a valid basket exists; it does not need to produce the same basket shown in the example.
