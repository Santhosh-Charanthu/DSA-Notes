GFG — Cake Distribution Problem

🔗 Problem

1. Why this comes under Binary Search on Answers

We need to maximize the minimum sweetness among exactly k + 1 contiguous pieces.

We are not searching for an element in the array. We are searching for the maximum possible value of the minimum piece sweetness.

For a candidate mid:

  • If we can make at least k + 1 pieces, each having sweetness >= mid → mid is possible.
  • If we cannot make k + 1 such pieces → mid is impossible.

As mid increases, it becomes harder to create pieces with sweetness at least mid:

TRUE TRUE TRUE TRUE FALSE FALSE FALSE

So this is Binary Search on Answer → Maximize the Minimum → Last TRUE.

2. What is the answer I'm searching for?

We are searching for the maximum possible minimum sweetness among the k + 1 pieces.

mid = minimum sweetness that we want every piece to have

For example:

mid = 9

means:

"Can I divide the cake into k + 1 pieces such that every piece has sweetness at least 9?"

The answer is the largest mid for which this is possible.

3. What is the smallest possible answer?

A valid lower bound is the minimum sweetness of an individual chunk.

low = min(sweetness)

Why?

Every piece contains at least one chunk, so its sweetness cannot be less than the minimum chunk sweetness.

For example:

sweetness = [6, 3, 2, 8, 7, 5]

Then:

low = 2

A smaller value such as 1 would also be a valid theoretical lower bound, but min(sweetness) is a tighter lower bound and is used in this solution.

4. What is the largest possible answer?

sum(sweetness).

In the extreme case, the entire cake could be considered as one piece, so the total sweetness is an upper bound.

Therefore:

high = sum(sweetness)

So the search range is:

min(sweetness) <= answer <= sum(sweetness)

5. If I assume mid is the answer

Assume:

mid = minimum sweetness required for every piece

Now scan the cake from left to right.

Keep adding chunks to the current piece.

As soon as:

currentSum >= mid

we have successfully created one valid piece.

So:

pieces++

and start building the next piece.

If pieces >= k + 1

We have enough valid pieces, so mid is possible.

But we want to maximize the minimum sweetness, so try a larger value:

low = mid + 1

If pieces < k + 1

We cannot create enough pieces with sweetness at least mid.

Therefore mid is too large:

high = mid - 1

Therefore:

possible → RIGHT

not possible → LEFT

We are looking for the last TRUE.

6. Main idea of isPossible()

For a candidate mid:

  1. Start with sum = 0.
  2. Traverse the chunks from left to right.
  3. Add each chunk to the current piece.
  4. Whenever sum >= mid, we have created one valid piece.
  5. Increase pieces and reset sum to start the next piece.
  6. At the end, check whether we created at least k + 1 pieces.

Example

sweetness = [6, 3, 2, 8, 7, 5]

k = 2

Therefore we need:

k + 1 = 3 pieces

Suppose:

mid = 9

Traverse:

6 + 3 = 9 → piece 1 ✅

Reset.

2 + 8 = 10 → piece 2 ✅

Reset.

7 + 5 = 12 → piece 3 ✅

Therefore:

pieces = 3

Since:

pieces >= k + 1

mid = 9 is possible.

Why do we check pieces >= k + 1 instead of pieces == k + 1?

The greedy process may create more than k + 1 valid pieces.

That is still feasible.

If we create extra pieces, we can merge adjacent pieces together until exactly k + 1 pieces remain.

Since all sweetness values are positive, merging pieces only increases their sweetness, so every resulting piece will still have sweetness >= mid.

Therefore:

pieces >= k + 1 → possible.

Key greedy idea

For a fixed minimum sweetness mid, create a piece as soon as its sweetness reaches mid.

This creates valid pieces as early as possible and leaves the remaining chunks available for the remaining pieces.

7. Main intuition

Simple idea

We don't know the maximum minimum sweetness, so guess it as mid.

Then ask:

"Can I cut the cake into at least k + 1 contiguous pieces, where every piece has sweetness at least mid?"

If yes, mid works, so try to demand even more sweetness.

If no, mid is too large, so reduce it.

In one flow

Answer = maximum possible minimum sweetness

→ Search in [min(sweetness), sum(sweetness)]

→ Assume mid is the required minimum sweetness

→ Greedily accumulate chunks

→ Whenever sum >= mid, create a piece

→ Count the pieces

→ pieces >= k + 1 → possible → go RIGHT

→ pieces < k + 1 → impossible → go LEFT

→ Return the last feasible value

Pattern to remember

Maximize the Minimum → Binary Search on Answer → Last TRUE → if mid works, move RIGHT.

⭐Important implementation points
  • There must be exactly k + 1 final non-empty contiguous pieces.
  • The feasibility check can look for at least k + 1 pieces because extra valid pieces can be merged.
  • The pieces must remain contiguous; we cannot choose arbitrary chunks.
  • The greedy check creates a piece immediately when its sum reaches mid.
  • low = min(sweetness) is a valid tighter lower bound.
  • high = sum(sweetness) is the maximum possible upper bound.
  • For large constraints, use long for sum and binary-search bounds if necessary to avoid overflow.
