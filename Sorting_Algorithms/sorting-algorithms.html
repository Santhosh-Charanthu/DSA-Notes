SORTING ALGORITHMS

🔹 1. Bubble Sort

💡 Intuition (Visual Thinking)

Imagine bubbles in water 🫧 👉 Larger elements "bubble up" to the end after each pass.

After every iteration:

  • The largest unsorted element moves to its correct position

⚙️ Core Idea

  • Compare adjacent elements
  • Swap if they are in wrong order
  • Repeat for all elements

⏱️ Complexity

Case Time Complexity
Best O(n) (optimized version)
Average O(n²)
Worst O(n²)

Space Complexity: O(1) (in-place)

💻 Java Code

public class BubbleSort {

    public static void bubbleSort(int[] arr) {
        int n = arr.length;
        boolean swapped;

        for (int i = 0; i < n - 1; i++) {
            swapped = false;

            for (int j = 0; j < n - i - 1; j++) {
                if (arr[j] > arr[j + 1]) {
                    // swap
                    int temp = arr[j];
                    arr[j] = arr[j + 1];
                    arr[j + 1] = temp;
                    swapped = true;
                }
            }

            // Optimization: stop if already sorted
            if (!swapped) break;
        }
    }

    public static void main(String[] args) {
        int[] arr = {5, 3, 8, 4, 2};
        bubbleSort(arr);
        for (int num : arr) {
            System.out.print(num + " ");
        }
    }
}

💡 Why n - i - 1 in Bubble Sort?

🔥 Core Idea

After every outer loop iteration:

👉 The largest element in the unsorted part is already placed at the correct position (end)

So we don't need to compare it again

🔹 2. Selection Sort

💡 Intuition (Think Like This)

👉 "Find the smallest element and put it in the correct place"

Instead of bubbling the largest to the end (like Bubble Sort), we select the minimum and place it at the beginning

⚙️ Core Idea

For every index i:

  1. Assume i is minimum
  2. Search for actual minimum in remaining array
  3. Swap with i

⏱️ Complexity

Case Time Complexity
Best O(n²)
Average O(n²)
Worst O(n²)
  • Space Complexity: O(1) (in-place)

👉 Important: Even if array is sorted, it still checks everything → no optimization like Bubble Sort

💻 Java Code

public class SelectionSort {

    public static void selectionSort(int[] arr) {
        int n = arr.length;

        for (int i = 0; i < n - 1; i++) {
            int minIndex = i;

            // find minimum element
            for (int j = i + 1; j < n; j++) {
                if (arr[j] < arr[minIndex]) {
                    minIndex = j;
                }
            }

            // swap
            int temp = arr[minIndex];
            arr[minIndex] = arr[i];
            arr[i] = temp;
        }
    }

    public static void main(String[] args) {
        int[] arr = {5, 3, 8, 4, 2};
        selectionSort(arr);
        for (int num : arr) {
            System.out.print(num + " ");
        }
    }
}

🎯 Interview Insight

👉 Selection Sort is useful when:

  • Swapping is costly
  • You want minimum swaps

🔹 3. Insertion Sort (🔥 Highly Important)

This one is:

  • Used in real systems (like TimSort)
  • Very strong for interviews

💡 Real-Life Intuition (This will click)

🃏 Think of Playing Cards in Your Hand

When you get cards, you don't randomly sort everything again.

👉 You do this:

  1. Hold already sorted cards in your hand
  2. Pick a new card
  3. Insert it into the correct position

⚙️ Core Idea

  • Maintain a sorted left portion
  • Take one element
  • Shift elements right to make space
  • Insert at correct position

⏱️ Complexity

Case Time Complexity
Best O(n) (already sorted)
Average O(n²)
Worst O(n²)

Space Complexity: O(1)

💻 Java Code

public class InsertionSort {

    public static void insertionSort(int[] arr) {
        int n = arr.length;

        for (int i = 1; i < n; i++) {
            int key = arr[i];   // element to insert
            int j = i - 1;

            // shift elements greater than key
            while (j >= 0 && arr[j] > key) {
                arr[j + 1] = arr[j];
                j--;
            }

            // place key at correct position
            arr[j + 1] = key;
        }
    }

    public static void main(String[] args) {
        int[] arr = {5, 3, 8, 4, 2};
        insertionSort(arr);
        for (int num : arr) {
            System.out.print(num + " ");
        }
    }
}

🔹 4. Merge Sort (Divide & Conquer)

💡 Intuition (This is EVERYTHING)

👉 "Break → Sort → Merge"

Instead of sorting directly:

  1. Divide array into halves
  2. Sort each half recursively
  3. Merge sorted halves

⚙️ Core Idea

👉 Recursively divide 👉 Merge sorted arrays using two pointers

⏱️ Complexity

Case Time Complexity
Best O(n log n)
Average O(n log n)
Worst O(n log n)

Why?

  • Splitting: log n levels
  • Merging: n work each level

📦 Space Complexity

👉 O(n) (extra array needed for merging)

💻 Java Code

public class MergeSort {

    public static void mergeSort(int[] arr, int left, int right) {
        if (left >= right) return;

        int mid = left + (right - left) / 2;

        // divide
        mergeSort(arr, left, mid);
        mergeSort(arr, mid + 1, right);

        // merge
        merge(arr, left, mid, right);
    }

    public static void merge(int[] arr, int left, int mid, int right) {
        int n1 = mid - left + 1;
        int n2 = right - mid;

        int[] leftArr = new int[n1];
        int[] rightArr = new int[n2];

        // copy data
        for (int i = 0; i < n1; i++)
            leftArr[i] = arr[left + i];

        for (int j = 0; j < n2; j++)
            rightArr[j] = arr[mid + 1 + j];

        int i = 0, j = 0, k = left;

        // merge arrays
        while (i < n1 && j < n2) {
            if (leftArr[i] <= rightArr[j]) {
                arr[k++] = leftArr[i++];
            } else {
                arr[k++] = rightArr[j++];
            }
        }

        // remaining elements
        while (i < n1) {
            arr[k++] = leftArr[i++];
        }

        while (j < n2) {
            arr[k++] = rightArr[j++];
        }
    }

    public static void main(String[] args) {
        int[] arr = {5, 3, 8, 4, 2};
        mergeSort(arr, 0, arr.length - 1);
        for (int num : arr) {
            System.out.print(num + " ");
        }
    }
}

💡 What are we trying to do here?

In merge sort, at some point you have:

👉 Two sorted halves, and you want to merge them

arr = [ ... left part ... | ... right part ... ]
        left → mid          mid+1 → right

🧠 Example (Fix this in your mind)

arr = [5, 3, 8, 4, 2]

Suppose:

left  = 0
mid   = 2
right = 4

So array is split as:

Left part  → [5, 3, 8]   (index 0 to 2)
Right part → [4, 2]      (index 3 to 4)

🔹 Why n1 = mid - left + 1 ?

👉 We want number of elements in left part

Formula:

n1 = (last index - first index) + 1

So:

n1 = mid - left + 1
   = 2 - 0 + 1
   = 3

✔️ Correct → [5, 3, 8] has 3 elements

🔹 Why n2 = right - mid ?

👉 Right part starts from mid + 1

So number of elements:

n2 = right - mid
   = 4 - 2
   = 2

✔️ Correct → [4, 2] has 2 elements

🔥 Why create leftArr and rightArr?

int[] leftArr = new int[n1];
int[] rightArr = new int[n2];

👉 Because merging directly inside original array is messy

So we:

  • Copy left part → leftArr
  • Copy right part → rightArr

Then merge cleanly

🔹 Copying Logic (Very Important)

Left Array

leftArr[i] = arr[left + i];

👉 Why left + i?

Because:

  • Left part starts at index left
  • We move forward using i

Example:

i = 0 → arr[0] = 5
i = 1 → arr[1] = 3
i = 2 → arr[2] = 8

✔️ So:

leftArr = [5, 3, 8]

Right Array

rightArr[j] = arr[mid + 1 + j];

👉 Why mid + 1 + j?

Because:

  • Right part starts at mid + 1
  • Then move forward using j

💡 Why is k = left?

🎯 Direct Answer

👉 Because we must place the merged (sorted) elements back into the same portion of the original array — starting exactly where this subarray begins.

🔹 5. Quick Sort (Divide & Conquer)

💡 Intuition (This is EVERYTHING)

👉 "Pick → Partition → Repeat"

Instead of dividing the array into equal halves like Merge Sort:

  1. Choose one element as the Pivot
  2. Place the Pivot in its correct position
  3. Everything smaller goes left
  4. Everything larger goes right
  5. Repeat for left and right parts

Quick Sort doesn't sort the pivot. It simply puts the pivot where it belongs.

⚙️ Core Idea

👉 Choose a Pivot

👉 Partition the array

👉 Pivot reaches its final sorted position

👉 Recursively sort left and right parts

🧠 Visualization

Before

5 3 8 4 2
        ↑
      Pivot

        ↓

After Partition

2 | 5 3 8 4
↑
Pivot fixed forever

        ↓

Sort Right

2 3 4 8 5

        ↓

2 3 4 5 8

Notice:

Every pivot reaches its final position.

⏱️ Complexity

Case Time Complexity
Best O(n log n)
Average O(n log n)
Worst O(n²)

Why?

Each partition takes

O(n)

If pivot divides the array roughly into half every time,

Levels = log n
Work each level = n
Total = O(n log n)

Worst case:

Already sorted array

1 2 3 4 5

Choosing last element every time gives

n levels
   ↓
O(n²)

📦 Space Complexity

Average : O(log n)
Worst   : O(n)

Only recursion stack is used.

No extra arrays are created.

👉 Quick Sort is an in-place sorting algorithm.

💻 Java Code

public class QuickSort {

    public static void quickSort(int[] arr, int low, int high) {
        if (low < high) {
            int pivotIndex = partition(arr, low, high);

            quickSort(arr, low, pivotIndex - 1);
            quickSort(arr, pivotIndex + 1, high);
        }
    }

    public static int partition(int[] arr, int low, int high) {
        int pivot = arr[high];
        int i = low - 1;

        for (int j = low; j < high; j++) {
            if (arr[j] < pivot) {
                i++;
                int temp = arr[i];
                arr[i] = arr[j];
                arr[j] = temp;
            }
        }

        int temp = arr[i + 1];
        arr[i + 1] = arr[high];
        arr[high] = temp;

        return i + 1;
    }

    public static void main(String[] args) {
        int[] arr = {5, 3, 8, 4, 2};
        quickSort(arr, 0, arr.length - 1);
        for (int num : arr) {
            System.out.print(num + " ");
        }
    }
}

💡 What are we trying to do here?

In Quick Sort, our goal is NOT to sort the entire array in one step.

Our goal is only:

Place one element (Pivot) in its correct position.

After that,

everything smaller will be on its left,

everything larger will be on its right.

🔹 Why choose arr[high] as Pivot?

int pivot = arr[high];

This implementation simply chooses

Last element as Pivot

Example

5 3 8 4 [2]

Pivot = 2

Other implementations may choose:

  • First element
  • Middle element
  • Random element

But here,

we always choose the last element.

🔹 Why i = low - 1?

int i = low - 1;

This is the most confusing line.

Remember this forever:

i always points to the last element that is smaller than the Pivot.

Initially,

we haven't found any smaller element.

So

i = low - 1

Example

low = 0
i = -1

Meaning

Smaller Elements
None

🔹 Why does j start from low?

for(int j = low; j < high; j++)

Because

j is the explorer.

Its job is

Check every element one by one.

Example

j checks

5
↓
3
↓
8

Notice

It never checks

🔹 Why j < high ?

Because

high

We never compare Pivot with itself.

So

j < high

is correct.

🔹 What does this condition mean?

if(arr[j] < pivot)

It means

Is this element smaller than the Pivot?

If YES,

move it to the left side.

Otherwise,

leave it on the right side.

🔹 Why do we increment i?

i++;

Because

we found one more element

that belongs on the left side.

So

our "smaller elements region"

Think of i as

Boundary of smaller elements.

🔹 Why swap arr[i] and arr[j]?

arr[i] = arr[j];
arr[j] = temp;

Suppose

Current situation

When

Result

🔹 Why do we swap Pivot at the end?

At this point

Left Side  → Smaller
Right Side → Greater
Pivot      → Last

Example

Pivot is still at the end.

Swap

7

with

Result

Now

Pivot is exactly where it belongs.

🔹 Why return i + 1?

Because

after the final swap,

the Pivot is stored at

That index is

Pivot's final sorted position.

Example

4 2 1 5 7
      ↑
Pivot Index = 3

So

return 3;

🔹 Why

quickSort(arr, low, pivotIndex - 1);

Because

everything left of Pivot

is still unsorted.

Sort it recursively.

🔹 Why

quickSort(arr, pivotIndex + 1, high);

Because

everything right of Pivot

is also unsorted.

Sort it recursively.

🔹 Base Condition

Meaning

Does this part contain

more than one element?

If

5

Only one element.

Already sorted.

Stop recursion.

🎯 Meaning of Every Variable

Variable Meaning

🔥 Interview One-Liner

Quick Sort is a Divide and Conquer algorithm that selects a pivot, partitions the array so that smaller elements are on the left and larger elements are on the right, places the pivot in its correct sorted position, and then recursively sorts the left and right partitions.
